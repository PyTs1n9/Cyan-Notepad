# 背景图毛玻璃的分层规则（主卡片更透 / 侧栏更深）

日期：2026-10-24
关联：`docs/prompt-workspace-shell-and-glass.md`（D10、§4.1–§4.4）

## 目标

有背景图时，三张浮卡当前的层次与直觉相反：**中间的主卡片最实**（`max(tintBg, 88)`），
左右侧栏更透（用户滑块，实测 83%）。诉求是把层次翻过来——**中间透、两边实**，
并且方向在四个主题下都不能反转。

## 结论

| # | 结论 | 理由 |
|---|---|---|
| 1 | 主卡片 tint 由侧栏 tint **派生**：`min(clamp(tintBg − 20, 40, 76), max(tintBg − 6, 0))` | 侧栏 tint 是用户滑块。写死主卡片值会在用户拖动滑块后与侧栏交叉；派生的语义是"侧栏永远比主卡片深一档"，任何滑块位置都成立 |
| 2 | 侧栏基色在背景图模式下压暗 15%（`--glass-panel-side`） | 深色主题 `--color-bg-sidebar (#1e1f23)` 比 `--color-bg-primary (#1a1b1e)` **更亮**，只提 tint 会让侧栏反而变浅；压基色在深／浅两类主题下方向一致 |
| 3 | 背景图配置的侧栏 tint 默认 80 → **83** | 侧栏是层级锚点，比基础配置更实一档；同时让"默认预设"等于实测验收过的一组数（83 / −20 / 15%） |
| 4 | 主卡片**不加**独立模糊 | 用户把背景图模糊调到 4px 就是为了看清壁纸；给主卡片单独提模糊与此意图直接冲突。可读性靠 tint 差值控 |
| 5 | 弹窗不复用主卡片 tint，走 `--glass-tint-dialog`（`max(tint, 88)`） | 设置／关于／更新／登录是叠在应用上的临时面，不参与三盒的深度阶梯，否则正文会落到壁纸上 |

`min(..., tintBg − 6)` 这一项是防反向：滑块拖到 20 时 `20 − 20 = 0` 会被下限顶到 40，
反而比侧栏更深，必须再夹一次。

## 实测（无头 Chrome 截图 + 同坐标取样，深色主题，正文 `#e9ecef`）

| 场景 | 表面 | 改前 | 改后 |
|---|---|---|---|
| 真实壁纸 | 主卡片 | luma 38，对比度 12.9:1 | luma 62，**9.4:1** |
| 亮色测试底 | 主卡片 | luma 51，10.8:1 | luma 99，**5.4:1** |
| 真实壁纸 | 侧栏 | luma 48 | luma 46 |
| 亮色测试底 | 侧栏 | luma 75 | luma 72 |

- 真实壁纸（暗调照片）下主卡片仍有 9.4:1，安全余量充足。
- 换成亮色壁纸时掉到 5.4:1：仍高于 WCAG AA 的 4.5:1，但已在边缘。这是差值 20 的代价，
  要更大余量就把差值收到 16（主卡片 67%，约 6.8:1）。

## 已知取舍

- **深色主题下"侧栏更深"的幅度有限**：15% 基色压暗在深色主题只降 4–5 luma，浅色主题降得更多。
  原因是深色面板本身已接近黑，能压的空间就小。若日后仍觉得不够，可给背景图模式加
  `railTint = clamp(tintBg + 5, 0, 100)` 的派生（代价：滑块读数比实际渲染低 5 档）。
- 主卡片下限 40 是"长文还能读"的经验值，不是硬性可访问性结论；若有用户把滑块拖到很低又用亮色壁纸，
  正文会接近 4.5:1 的下边缘。
