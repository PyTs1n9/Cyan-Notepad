# 决策记录：待办子项（subtask）

日期：2026-10-22
状态：待确认后执行

## 背景

现状：`Todo` 是扁平结构（`id / listId / order / priority / pinned / dueDate / completed`），
`todoStore` 的 `sortTodos`、`normalizeTodoOrders`、`reorderTodos`、`getNextTodoOrder` 全部按
`listId + pinned + completed` 三元组分组；`TodoView` 直接 `listTodos.map(...)` 平铺渲染。

需求：待办可以带「子待办」，并在父行上展开/收起查看。

影响面：排序分组键、重排、删除、筛选、顶部统计、侧边栏计数、`todos.json` 数据形态，
以及 `TodoView` 的行渲染结构。共 6 处逻辑 + 1 处数据兼容。

## 结论

### 1. 层级深度

结论：只做一层。父待办可展开，子待办不能再挂子项。
理由：现有排序/重排算法是单层的，加一层只需在分组键里追加 `parentId`；无限嵌套需要递归
渲染、递归排序与递归删除，拖拽跨层级语义也要重新定义，收益不足以抵消复杂度。

### 2. 完成联动

结论：单向级联。勾选父待办 → 其所有子待办一并置为完成；取消父待办 → 子项保持原状，
不反向联动。子项全部勾选也不自动完成父项。
理由：反向联动（子全勾→父完成、取消子→父取消）会让父项状态变成子项的附属品，用户在父行上
的操作结果会被后续子项操作悄悄改写。父行改为显示 `已完成子项/子项总数` 进度，信息不缺。

### 3. 子项能力边界

结论：子行只有「勾选圈 + 标题内联编辑 + 删除」。没有优先级标签、截止日期、置顶、拖拽。
理由：子项定位是拆解步骤，不是重量的独立任务；给全能力会让每行高度与父行趋同，
展开后的视觉层级失效，也让优先级筛选、置顶等既有逻辑要多考虑一层。

### 4. 统计口径

结论：顶部「完成数/总数 + 完成率」、侧边栏待办计数、列表右侧未完成计数，均只统计父项。
子项进度以 `2/5` 形式显示在父行内。
理由：父子同时计数会把同一件事计量两次，完成率失真（一个父项带 5 个子项会占 6 个名额）。

### 5. 添加入口

结论：父行 hover 时在操作区出现「+ 子项」按钮，点击后立即在该父项下创建一条空子项并
进入内联编辑；若父项处于收起状态，创建时自动展开。
理由：不强制先展开才能加，减少一次点击；复用现有 `editingId` 内联编辑链路，不新增弹窗。

### 6. 展开态持久化

结论：持久化。展开态以 `expanded?: boolean` 存在父项自身记录里，随 `todos.json` 走现有自动保存。
理由：不需要新增存储文件与加载链路；新建父项默认收起，避免列表一次性全部撑开。

### 7. 拖拽范围

结论：拖拽只在主层级，父项之间可排序。子项按创建顺序固定排列。
理由：子项拖拽要么需要「同父内重排」，要么需要「跨父移动（等于改父）」，两者都要新的放置
高亮与落点判定；当前拖拽实现基于 `listRef.children` 平铺索引，混入子行后需要重写索引映射。

### 8. 筛选联动

结论：「全部/未完成/已完成」与优先级筛选只作用于父项；展开后子项全部显示，不受筛选影响。
理由：子项被筛掉会留下「父项在、展开却是空的」的空壳状态，用户无法判断是没子项还是被过滤。

### 9. 删除行为

结论：删除父项 = 级联删除其全部子项，沿用现有确认弹窗；删除子项直接生效，不弹确认。
理由：子项丢失成本低，逐条确认会打断拆解流程；父项确认弹窗文案需说明会连带删除子项。
置顶父项仍不可删除（沿用 `deleteTodo` 现有约束）。

### 10. 旧数据兼容

结论：`parentId` 缺失或为空的记录一律视为父项，无需迁移脚本。
理由：新字段可选，旧 `todos.json` 读入后自然落在主层级，`normalizeTodoOrders` 用
`parentId ?? null` 作为分组键即可。

## 实现约定（技术默认值，无需另行确认）

- `Todo` 增加 `parentId?: string | null` 与 `expanded?: boolean`；子项 `pinned` 恒为 `false`。
- `normalizeTodoOrders` / `getNextTodoOrder` 的分组键追加 `parentId ?? null`，其余分组维度不变。
- `todoStore` 新增 `addSubtask(parentId, title)`、`toggleExpanded(id)`；`addTodo` 保持只建父项。
- `toggleTodo` 在目标为父项且即将置为完成时，同批把其子项置为完成。
- `deleteTodo` 在目标为父项时同批删除 `parentId === id` 的记录。
- `reorderTodos` 增加同 `parentId` 校验，避免子项与父项互串。
- `TodoView` 渲染改为「父项行 + 子项列表块」；子行缩进对齐标题列，`space-y-1` 容器不变。
- 父行进度徽标仅在存在子项时显示，复用 `text-xs` + `text-text-muted`。
- i18n 新增词条：`subtask`、`addSubtask`、`expandSubtasks`、`collapseSubtasks`、`deleteSubtask`、
  `confirmDeleteTodoWithSubtasks`（中英各一套，`src/utils/i18n.ts` 的 typed table）。
