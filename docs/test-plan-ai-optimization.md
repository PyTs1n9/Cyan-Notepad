## 1. 会话分片迁移（风险最高，先看）

已发生的部分：磁盘上 `data/ai/chats/` 有 1 个分片（16 条消息），旧的 `chats.json` 已删除
——迁移在真实数据上跑过一次。

待你确认的行为：

1. 侧栏历史弹层能列出原会话，标题、消息数正确。
2. 切到另一个会话再切回来，内容一致。
3. 新发一轮消息后，`data/ai/chats/<id>.json` 的 `updatedAt` 变化，且**只有当前会话那个文件**被改写。
4. 删除一个会话后，对应分片文件消失。

失败特征：会话列表为空 / 消息丢失 / `chats/` 下出现多个同名重复分片 / 删会话后文件仍在。

## 2. 链接协议拦截（安全项）

1. 新建笔记，粘贴：`[危险](javascript:alert(1))` 与 `[正常](https://example.com)`。
2. 切到预览视图。

通过：危险的只显示「危险」两个字（无下划线、不可点）；正常的仍是可点链接。
失败特征：危险的渲染成可点链接，或点击后控制台出现 `alert` / 脚本报错。

## 3. 写笔记：撤销条 + diff

1. AI 侧栏权限切到「完全开放」（会弹一次风险确认）。
2. 对《AI 测试》说：「把这篇笔记的标题改成 AI 测试 2，正文末尾加一行『由 AI 追加』」。
3. 观察：回答下方出现琥珀色编辑 chip；**输入框上方**出现同一提示条，5 秒后自动消失。
4. 点 chip → 展开行级 diff（`+` 绿、`-` 红）。
5. 点提示条或 chip 旁边的「撤销」→ 笔记回到修改前。

失败特征：提示条不出现 / 5 秒后不消失（或提前消失）/ diff 空白 / 撤销后正文没变 /
撤销后 chip 仍显示为"已修改"。

## 4. 阶段文案（三种等待要能区分）

| 操作 | 期望占位文案 |
| --- | --- |
| 模型选「小青」，提问 | 正在检索本地知识库… |
| 完全开放权限下让它改笔记 | 「正在处理笔记…」 |

注意：索引已预热时「正在检索」可能一闪而过，这是正常的，不是 bug。
失败特征：各阶段仍显示同一句「正在思考…」，或文案与阶段错位（如检索阶段显示"处理笔记"）。
（注：联网搜索已移除，原「正在联网搜索…」一行随之删除。）

## 5. 来源 chip

1. DeepSeek 模式 + 联网开启，问一个时效性问题（如「今天有什么科技新闻」）。
2. 回答下方应出现「参考来源」+ 若干 chip（站点名或域名）。
3. 点一个 chip。

通过：系统默认浏览器打开该页面，**应用本身不跳转**、不白屏。
失败特征：应用窗口被导航走 / 点了没反应 / chip 显示 `[object Object]` / 无来源但联网成功。

## 6. 截断提示

1. DeepSeek 推理模式下让它写超长内容：「详细写一份 5000 字的项目计划」。
2. 看回答末尾。

通过：出现琥珀色「回答达到长度上限，内容可能被截断。」
失败特征：回答明显不完整但没有任何提示（即 `finish_reason` 没被捕获）。

## 7. 流式重渲染（性能，只能体感 + 粗略测量）

1. 打开一个 20 轮以上的长会话。
2. 发一条需要长回答的问题，观察流式过程。
3. 可选：DevTools → Performance 录一段，看主线程长任务。

通过：滚动跟随流畅，输入框可正常输入，无明显掉帧。
失败特征：流式期间输入卡顿、滚动跳动、整段重排闪烁。

## 8. 首问冷启动（预热）

1. 在任意笔记里改一个字（触发索引重建）。
2. 等 3–5 秒（idle 预热窗口），提问。
3. 对比：改完立刻提问 vs 等 5 秒再提问，感受首字延迟差异。

失败特征：控制台出现 `ai: chunk warmup stopped` / 首问仍要等数秒且每次都这样。
