# 决策记录：AI 生成内容滚动跟随（2026-10-22）

## 背景

AI 流式生成内容时画面定在原地，不随内容增长滚动。排查结论：

- `AiSidebar.tsx` 原跟随逻辑挂在 `[messages]` 上，但回答气泡的 Markdown 是 160ms 防抖后异步渲染的，滚动执行时内容高度尚未增长；内容增速一旦超过 80px 的 near-bottom 阈值，跟随即失效，画面冻结。
- `AiPolishPanel.tsx` 流式生成完全没有跟随，加载态/结果出现在折叠线以下。
- `ReasoningBlock` 的 `max-h-40` 内部滚动区不跟随推理流增长。

## 结论

| 主题 | 决定 | 理由 |
| --- | --- | --- |
| 跟随机制 | ResizeObserver 观察内容元素高度，增长即钉底 | 捕捉 Markdown 异步渲染等"渲染后长高"的场景，不依赖 store 更新时机 |
| 用户上滑行为 | 上滑离开底部即暂停跟随，滚回底部附近自动恢复；新一轮生成开始/切换会话时重新武装并钉底 | 既不打断用户回看历史，又不会出现回不到最新内容的死角（业界主流交互） |
| 适用范围 | 统一用于 AI 聊天气泡流 + 思考过程块 + AI 润色面板 | 三处是同一交互规则，一次定好避免行为不一致 |
| 滚动方式 | 瞬时钉底（`scrollTop = scrollHeight`），不用平滑滚动 | 流式期间平滑滚动会累积动画、产生抖动 |
| 跟随阈值 | 消息区/润色面板 80px，思考过程块 40px | 小滚区等比缩小"视为在底部"的判定范围 |
| 实现位置 | 共享 hook `src/hooks/useStreamScroll.ts` | 单一规则单一实现，后续流式界面可直接复用 |
