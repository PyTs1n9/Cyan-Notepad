# 侧栏文件树改造 — 决策记录

日期：2026-10-22
主题：把左侧「分类列表 + 笔记平铺列表」改造成开发工具风格的文件树，右键菜单承载重命名/置顶/删除等操作。

## 背景事实（已核实，非假设）

- 侧栏现状：上半为扁平分类列表（计数、hover 改名/删除、自定义鼠标拖拽排序），下半为被 `activeCategoryId` 过滤的笔记平铺列表，中间是可拖拽分隔条，比例存 `sidebarCategoryRatio`。
- `NoteCategory` 只有 `id / name / order / createdAt`：**无 parentId，无 pinned**。
- `Note.title` 是独立字段，编辑器内可直接改（`updateNote(id, { title })`），storage 缺省时从正文首行派生。树内重命名有落点，不需要新机制。
- `deleteCategory` 现行为：把该分类下笔记的 `categoryId` 置 `null`（落到「未分类」），**不删笔记**，也不处理子分类（当前无子分类）。
- 回收站只支持笔记文件与图片（`data/trash/notes/`、`data/img-trash/`），**没有分类回收站**。
- `getFilteredNotes` 按 `searchQuery` + `filterTag` + `activeCategoryId` 过滤，`pinned` 恒排最前。
- `noteStore` 的 order 归一化按 `(categoryId, pinned)` 分组，`reorderNotes` 禁止跨分类、禁止动 pinned 项。

## 结论

### 1. 树层数 — 无限嵌套

- 结论：分类支持任意层父子关系，`NoteCategory` 新增 `parentId?: string | null`。
- 理由：用户明确要求。单层与多层的渲染器可以共用一套递归实现，先按现有扁平数据渲染，后续填充 `parentId` 即可，不必重写渲染层。

### 2. 缩进策略 — 递减缩进，不设硬上限

- 结论：缩进随深度递减（约 14px → 10px → 7px），并设 6px 下限；不做横向滚动，不设嵌套层数上限。
- 理由：侧栏宽度仅 240–320px，固定 14px 缩进在第 6 层就会吃掉一半宽度；硬上限会让「无限嵌套」名不副实；面包屑替换标题会让标题更难扫读。

### 3. 排序模型 — 同一父级下文件夹与笔记混排单一序列

- 结论：同一 `parentId` 下的子文件夹与笔记共用一条 `order` 序列，可任意插入到两者之间。
- 理由：自由度最高，且把「文件夹恒在前」这种隐式排序规则去掉了，用户拖到哪就是哪。代价是 `normalizeNoteOrders` 要从按 `(categoryId, pinned)` 分组改为按「父容器」分组，并让分类与笔记的 order 在同一序列内可比。

### 4. 置顶 — 分类与笔记都可置顶

- 结论：`NoteCategory` 新增 `pinned?: boolean`；置顶分类整体排到树顶，置顶笔记排在所属文件夹内最前。
- 理由：右键菜单对文件夹和文件语义一致，不会出现「为什么文件夹不能置顶」。不采用「树顶虚拟『已置顶』文件夹」，因为那会让笔记在树里丢失原始位置。

### 5. 删除语义 — 整个子树进回收站

- 结论：删除文件夹时，其子树内全部笔记进入回收站，并记录原始路径（父级链与分类名），支持整树恢复。
- 理由：现在「置 null 落到未分类」在嵌套模型下会把深层内容洗成一大片未分类，等于隐性数据损坏。代价是需要扩展回收站结构（回收站目前只认笔记文件），这是本改造中唯一要新增持久化结构的部分。

### 6. 布局 — 合并为单一滚动树

- 结论：分类面板与笔记列表合并为一个滚动区，移除中间分隔条与 `sidebarCategoryRatio` 的读写（旧值保留在 settings.json 中不删，只是不再读取）。
- 理由：树形本身就把两个列表合成一个层级结构，再分上下两段会让同一条笔记出现两次。旧设置不删除是为了回滚安全。

### 7. 搜索与标签过滤 — 命中节点 + 祖先链

- 结论：过滤时只保留命中节点及其祖先文件夹，并自动展开命中路径；其余节点隐藏。
- 理由：这是树形结构下唯一不丢失层级位置的表现方式；临时切成平铺列表会让「在这个文件夹里」的上下文消失。

### 8. 拖拽 — 去掉移动确认弹窗

- 结论：拖拽移动不再弹 `confirm`，改为落点高亮（已有 `drag-insertion-line` 与 `drag-target-inside`）+ 可撤销（回收站 / 拖回）。
- 理由：嵌套后移动是高频操作，每次弹窗会打断节奏；落点高亮已能表达意图。

### 9. 右键菜单 — 精简 5 + 4 项

- 文件夹：新建笔记 / 新建子文件夹 / 重命名 / 置顶 / 删除
- 笔记：重命名 / 置顶 / 移到文件夹… / 删除
- 结论：第一版只做这些，移除现有的 hover 小按钮（改名/删除/置顶/删除），统一收进右键菜单。
- 理由：hover 按钮在树形里会和展开箭头、缩进抢位置，且窄侧栏下容易误触。

### 10. 实现方式 — 手写递归树，零新依赖

- 结论：递归组件 + 复用现有自定义鼠标拖拽，不引入树组件库。
- 依据（npm registry 实时查询，2026-10-22）：
  - `react-arborist` 4.0.1（2026-10-11，MIT）：依赖 redux、react-window、@types/react-window，peer 还需 react-dnd 与 react-dnd-html5-backend。
  - `@headless-tree/core` / `@headless-tree/react` 1.8.0（2026-10-15，MIT）：零运行时依赖，但拖拽仍需自行绘制。
- 理由：笔记量约 40 篇，不需要虚拟化；项目已有自定义拖拽与主题体系，引库要额外对抗内置样式，且 react-arborist 会引入 redux 与 Zustand 并存两套状态。零依赖方案与现有代码风格一致。

### 11. 迁移安全 — 自动备份

- 结论：首次以新模型启动时，先把 `data/notes/index.json` 与分类数据复制到 `data/backup-<YYYYMMDD-HHmmss>/`，成功后才写入新结构；备份失败则中止迁移并保留旧结构。
- 理由：`data/notes/` 下已有真实笔记文件，模型改错即真实数据损失。仅靠 git 不能保护构建产物目录里的用户数据。

### 12. 交付节奏 — 分三段，逐段可验收

- 第一段：单滚动树形渲染 + 展开/折叠 + 递减缩进（可运行、可肉眼验收）
- 第二段：右键菜单（文件夹 5 项 / 笔记 4 项），移除 hover 小按钮
- 第三段：`parentId` 嵌套模型 + 同层混排排序 + 整树回收站 + 自动备份迁移

## 默认假设（未单独确认，按此执行，可随时推翻）

- 展开/折叠状态持久化到 `settings.json`，跨会话记住。
- 键盘支持做基础版：`↑ ↓` 移动焦点、`← →` 折叠/展开、`F2` 重命名、`Delete` 删除、`Shift+F10` 呼出右键菜单。
- 树内不显示文件扩展名，笔记图标区分置顶/普通，不区分文件类型。
- 「全部笔记」「未分类」保留为树顶的固定虚拟节点，不参与重命名/删除/置顶。
